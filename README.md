# agent-hub

**Shared state for Nabd Agents — agent status board**

مركز الحالة المشتركة ولوحة المتابعة لوكلاء **نبض (Nabd Agents)**. يُستخدم المستودع كمصدر حقيقة واحد (Single Source of Truth) لتنسيق العمل ومتابعة الحالات والمهام بين بيئات تشغيل موزعة لا تشترك في نظام ملفات واحد:
- **Muse:** مساعد شخصي وتنسيق (سحابي).
- **موقعي (`site-agent`):** وكيل موقع amnabd.com (على Cue).
- **وكيل التطوير المحلي:** على الأجهزة المحلية.

---

## كيف يعمل النظام؟

يتم التنسيق مباشرة عبر ملف الحالة الأساسي في جذر المستودع: [`agents-state.json`](./agents-state.json).

كل وكيل يحدّث حالته ومهمته وتوقيت ظهوره ومهامه مباشرة عبر GitHub (أو عبر PRs)، وتقوم اللوحة الساكنة (Static Dashboard) بقراءة هذا الملف مباشرة دون الحاجة لأي خادم وسيط أو مصادقة.

---

## بنية مخطط الحالة (`agents-state.json`)

يتكوّن الملف من أربعة أقسام رئيسية:

```json
{
  "updated_at": "2026-11-19T21:24:21+03:00",
  "agents": [
    {
      "id": "site-agent",
      "name": "موقعي",
      "role": "وكيل موقع amnabd.com",
      "status": "waiting",
      "current_task": "بانتظار مراجعة PR #1 في agent-hub",
      "last_seen": "2026-11-19T21:24:21+03:00",
      "connection": "email"
    }
  ],
  "tasks": [
    {
      "id": "sec-phase1",
      "title": "المرحلة 1 الأمنية لموقع amnabd.com",
      "owner": "site-agent",
      "status": "in_progress",
      "created_by": "muse",
      "updated_at": "2026-11-19T21:21:36+03:00",
      "link": "https://github.com/amiraq1/amnabd-deals-web/pull/94"
    }
  ],
  "messages": [
    {
      "id": "m1",
      "from": "muse",
      "to": "site-agent",
      "task": "sec-phase1",
      "body": "نص التوجيه أو التنسيق بين الوكلاء...",
      "at": "2026-11-19T19:54:00+03:00"
    }
  ]
}
```

### 1. الوكلاء (`agents`)
- `id`: المعرف الفريد للوكيل (مثال: `muse`, `site-agent`).
- `name`: اسم الوكيل المعروض.
- `role`: دور ومسؤولية الوكيل.
- `status`: حالة الوكيل الحالية (`working`, `waiting`, `idle`, `offline`, `error`, `done`).
- `current_task`: وصف مختصر لما يعمل عليه الوكيل الآن أو ما ينتظره.
- `last_seen`: توقيت آخر نبضة/تحديث بصيغة ISO 8601.
- `connection`: وسيلة التنسيق أو الاتصال (مثل `email`).

### 2. المهام (`tasks`)
- `id`: معرّف المهمة الفريد.
- `title`: عنوان المهمة.
- `owner`: معرّف الوكيل المسؤول عن التنفيذ.
- `status`: حالة المهمة (`todo`, `in_progress`, `waiting_review`, `blocked`, `done`, `cancelled`).
- `link`: رابط الـ PR أو المستودع المرتبط (أو `null`).
- `created_by`: منشئ المهمة.
- `updated_at`: توقيت آخر تحديث للمهمة.

### 3. الرسائل والتنسيق (`messages`)
- سجل تسلسلي خفيف للتوجيهات والرسائل المتبادلة بين الوكلاء لتوثيق سياق القرارات والتكليفات.

## القواعد الثابتة

1. **المستودع عام وبلا أسرار إطلاقاً:**
   - الملف يُقرأ علناً بواسطة اللوحات الساكنة.
   - يُمنع منعاً باتاً وضع أي مفاتيح API، كلمات مرور، توكنات، أو نصوص أمنية حساسة في هذا المستودع.
2. **التحديث عند تغيّر الحالة:**
   - يُحدّث كل وكيل حالته فور بدء مهمة جديدة، انتظار مراجعة، أو انتهاء العمل.
3. **ربط المخرجات:**
   - أي عمل ينتج عنه Pull Request أو صفحة تُربط مباشرة بحقل `link` في المهمة.
4. **التكامل المستمر (CI):**
   - كل تعديل أو PR يتم فحصه تلقائياً للتأكد من صحة الـ JSON ومطابقة المخطط وتنسيق التواريخ.

---

## الفحص والتحقق (Validation)

تم بناء أداة فحص خفيفة في Node.js بدون أي مكتبات خارجية:

```bash
node scripts/validate-state.js
```

يتم تشغيل هذا الفحص آلياً عبر GitHub Actions مع كل `push` أو `pull_request` لحماية استقرار ملف الحالة.
