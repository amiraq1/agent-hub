# agent-hub

**Shared state for Nabd Agents — agent status board**

🌐 **رابط اللوحة الحية (Live Dashboard):** [https://amiraq1.github.io/agent-hub/](https://amiraq1.github.io/agent-hub/)

مركز الحالة المشتركة ولوحة المتابعة لوكلاء **نبض (Nabd Agents)**. يُستخدم المستودع كمصدر حقيقة واحد (Single Source of Truth) لتنسيق العمل ومتابعة الحالات والمهام بين بيئات تشغيل موزعة لا تشترك في نظام ملفات واحد:
- **Muse:** مساعد شخصي وتنسيق (سحابي).
- **موقعي (`site-agent`):** وكيل موقع amnabd.com (على Cue).
- **وكيل التطوير المحلي:** على الأجهزة المحلية.

---

## كيف يعمل النظام؟

يتم التنسيق مباشرة عبر ملف الحالة الأساسي في جذر المستودع: [`agents-state.json`](./agents-state.json).

كل وكيل يحدّث حالته ومهمته وتوقيت ظهوره ومهامه مباشرة عبر GitHub (أو عبر PRs)، وتقوم اللوحة الساكنة (Static Dashboard) بقراءة هذا الملف مباشرة دون الحاجة لأي خادم وسيط أو مصادقة.

## بنية مخطط الحالة (`agents-state.json`)

يتكوّن الملف من أربعة أقسام رئيسية:

```json
{
  "updated_at": "2026-11-19T21:24:21+03:00",
  "agents": [
    {
      "id": "site-agent",
      "name": "موقعي",
      "role": "وكيل موقع amnabd.com",
      "status": "waiting",
      "current_task": "بانتظار مراجعة PR #1 في agent-hub",
      "last_seen": "2026-11-19T21:24:21+03:00",
      "connection": "email"
    }
  ],
  "tasks": [
    {
      "id": "sec-phase1",
      "title": "المرحلة 1 الأمنية لموقع amnabd.com",
      "owner": "site-agent",
      "status": "in_progress",
      "created_by": "muse",
      "updated_at": "2026-11-19T21:21:36+03:00",
      "link": "https://github.com/amiraq1/amnabd-deals-web/pull/94"
    }
  ],
  "messages": [
    {
      "id": "m1",
      "from": "muse",
      "to": "site-agent",
      "task": "sec-phase1",
      "body": "نص التوجيه أو التنسيق بين الوكلاء...",
      "at": "2026-11-19T19:54:00+03:00"
    }
  ]
}
```

### 1. الوكلاء (`agents`)
- `id`: المعرف الفريد للوكيل (مثال: `muse`, `site-agent`).
- `name`: اسم الوكيل المعروض.
- `role`: دور ومسؤولية الوكيل.
- `status`: حالة الوكيل الحالية (`working`, `waiting`, `idle`, `offline`, `error`, `done`).
- `current_task`: وصف مختصر لما يعمل عليه الوكيل الآن أو ما ينتظره.
- `last_seen`: توقيت آخر نبضة/تحديث بصيغة ISO 8601.
- `connection`: وسيلة التنسيق أو الاتصال (مثل `email`).

### 2. المهام (`tasks`)
- `id`: معرّف المهمة الفريد.
- `title`: عنوان المهمة.
- `owner`: معرّف الوكيل المسؤول عن التنفيذ.
- `status`: حالة المهمة (`todo`, `in_progress`, `waiting_review`, `blocked`, `done`, `cancelled`).
- `link`: رابط الـ PR أو المستودع المرتبط (أو `null`).
- `created_by`: منشئ المهمة.
- `updated_at`: توقيت آخر تحديث للمهمة.
- `handoff` *(اختياري)*: إيصال التسليم غير المتزامن بين الوكلاء لتوثيق التسليم والخطوة التالية.

### 3. إيصال التسليم الموثّق (`handoff`)
حقل اختياري داخل المهمة يُوثق عملية تسليم العمل بين وكيلين بدقة وأمانة:
```json
{
  "from": "site-agent",
  "to": "muse",
  "at": "2026-11-19T23:05:00+03:00",
  "status": "pending",
  "summary": "اكتمال المرحلة الاحترافية لتحسين السرعة والأداء الشامل لموقع amnabd.com بنجاح (633 اختبار)",
  "next_step": "مراجعة واعتماد PR #96 ودمجه إلى main",
  "evidence_url": "https://github.com/amiraq1/amnabd-deals-web/pull/96",
  "decision": {
    "by": "muse",
    "at": "2026-11-20T01:10:00+03:00",
    "reason": "ملاحظة مراجعة أو سبب الإعادة (إلزامي في حالة returned)"
  }
}
```
- `from`: معرّف الوكيل المرسل (يجب أن يكون مسجلاً في `agents`).
- `to`: معرّف الوكيل المستلم صاحب الخطوة التالية (يجب أن يكون مسجلاً في `agents`).
- `at`: توقيت التسليم بصيغة ISO 8601.
- `status`: حالة الإيصال:
  - `pending`: التسليم معلق بانتظار مراجعة المستلم.
  - `accepted`: قُبل التسليم (المهمة تظل جارية حتى اكتمال العمل الفعلي).
  - `returned`: أُعيد التسليم للتصحيح (يتطلب معالجة من المرسل).
- `summary`: ملخص ما تم إنجازه.
- `next_step`: الإجراء المطلوب بدقة من الطرف الآخر.
- `evidence_url` *(اختياري)*: رابط آمن للمخرجات (`http:` أو `https:`).
- `decision` *(اختياري عند accepted/returned)*:
  - `by`: الوكيل متخذ القرار.
  - `at`: توقيت القرار.
  - `reason`: سبب القرار (إلزامي وغير فارغ عند `returned`).

## «نبض | برج التنسيق — من عليه الخطوة التالية؟»

قسم مركزي في واجهة اللوحة يجيب خلال ثوانٍ معدودة عن:
1. **ما المهمة التي تحتاج تدخلاً الآن؟**
2. **من صاحب الخطوة التالية؟**
3. **ما الدليل أو القرار الذي ينتظره؟**

### قواعد الأولوية وترتيب المهام:
1. **التسليمات المعادة أولاً (`returned`):** أولوية قصوى لأن العمل متعثر بانتظار تصحيح المرسل (`from`) بناءً على `decision.reason`.
2. **التسليمات المعلقة (`pending`):** مرتبة تصاعدياً بحسب الأقدم (أطول فترة انتظار) لتنبيه المستلم (`to`) بسرعة المراجعة والبت.
3. **المهام المقبولة المفتوحة (`accepted`):** تسير في مسار التنفيذ الطبيعي ولا تزال المهمة قيد الإنجاز.
4. **المهام المكتملة أو الملغاة (`done`, `cancelled`):** تُستثنى تلقائياً لمنع الضوضاء.
5. **الحالة الفارغة الصادقة:** عند خلو اللوحة من مهام معلقة، يُعرض مؤشر أخضر صريح: *«لا توجد مهام تنتظر إجراءً حالياً — جميع المهام مكتملة أو تسير دون عوائق»*.

## سيناريو واقعي لدورة التسليم (Muse ↔ موقعي)

يوثق المستودع دورة التنسيق بين وكيل الموقع (`site-agent`) والوكيل المنسق (`muse`):

1. **إرسال التسليم (Pending):**
   - يُنهي `site-agent` تحسين أداء الموقع ويرفع PR #96، ثم يحدّث `agents-state.json`:
   - يضع `handoff.from = "site-agent"`, `handoff.to = "muse"`, `handoff.status = "pending"`.
   - يرفق رابط الدليل `https://github.com/amiraq1/amnabd-deals-web/pull/96`.
   - تظهر المهمة في برج التنسيق باللون الأصفر: صاحب الخطوة هو `muse` لمراجعة PR #96.

2. **الخيار أ — القبول والاعتماد (Accepted):**
   - يفحص `muse` الأدلة والـ PR، ويحدّث الحالة:
   - `handoff.status = "accepted"`.
   - `decision: { "by": "muse", "at": "2026-11-20T...", "reason": "تم فحص الـ PR ونجاح 633 اختباراً والموافقة على الدمج" }`.
   - تظل المهمة مفتوحة حتى يتم دمج الـ PR فعلياً، ثم تتحول إلى `task.status = "done"`.

3. **الخيار ب — الإعادة للتصحيح (Returned):**
   - إذا وجد `muse` نقصاً في التغطية أو كسر فحص:
   - يحدّث `handoff.status = "returned"`.
   - يضيف سبباً إلزامياً: `decision: { "by": "muse", "at": "...", "reason": "فحص bundle size تجاوز الميزانية بـ 5KB، يرجى ضغط الخطوط وإعادة الرفع" }`.
   - تنتقل المهمة فوراً في اللوحة إلى أعلى برج التنسيق باللون الأحمر؛ صاحب الخطوة يصبح `site-agent` لمعالجة السبب وإعادة التسليم.

## الأمانة المعرفية (Epistemic Honesty)

- **التسلسل المتاح (Available Sequence):** لا تدّعي اللوحة اكتمال السجل التاريخي إن لم يكن مسجلاً، بل تعرض الأحداث المتوفرة في ملف الحالة الحالي بترتيب زمني واضح مع إشارة صريحة.
- **فصل التواريخ الثلاثة:**
  1. *عمر انتظار التسليم:* كم مضى على تعليق الـ handoff؟
  2. *آخر نبضة للوكيل:* متى كانت آخر إشارة حياة للوكيل المسؤول؟
  3. *توقيت جلب البيانات:* هل المعروض الآن نسخة حية من GitHub أم نسخة مخزنة محلياً في المتصفح؟
- **إشعار التخزين المؤقت:** إذا كانت اللوحة تعمل بلا اتصال أو من الذاكرة المؤقتة، يظهر تنبيه بارز: *«نسخة مخزنة محلياً — قد لا تعكس آخر تحديث على GitHub»*.
- **روابط الأدلة:** فتح الرابط الخارجي للمشاهدة والتحقق فقط، ولا يعني قبول التسليم تلقائياً — فالتحديث يتم حصراً عبر تعديل ملف الحالة في Git.

### 4. الرسائل والتنسيق (`messages`)
- سجل تسلسلي خفيف للتوجيهات والرسائل المتبادلة بين الوكلاء لتوثيق سياق القرارات والتكليفات.

## القواعد الثابتة

1. **المستودع عام وبلا أسرار إطلاقاً:**
   - الملف يُقرأ علناً بواسطة اللوحات الساكنة.
   - يُمنع منعاً باتاً وضع أي مفاتيح API، كلمات مرور، توكنات، أو نصوص أمنية حساسة في هذا المستودع.
2. **التحديث عند تغيّر الحالة:**
   - يُحدّث كل وكيل حالته فور بدء مهمة جديدة، انتظار مراجعة، أو انتهاء العمل.
3. **ربط المخرجات:**
   - أي عمل ينتج عنه Pull Request أو صفحة تُربط مباشرة بحقل `link` في المهمة.
4. **التكامل المستمر (CI):**
   - كل تعديل أو PR يتم فحصه تلقائياً للتأكد من صحة الـ JSON ومطابقة المخطط وتنسيق التواريخ واجتياز اختبارات برج التنسيق.

## بنية الأداء والواجهة السريعة (Performance Architecture)

تمت ترقية الواجهة لتحقيق درجة **99-100 في Google Lighthouse**:
- **Zero Render-Blocking:** إزالة سكربتات Tailwind CDN وChart.js بالكامل؛ الاعتماد على CSS خفيف مسبق التجميع (`assets/styles.min.css`) ومخططات بيانية SVG متفاعلة أصلية (0 KB تبعيات خارجية).
- **Stale-While-Revalidate (SWR):** رسم فوري لأحدث حالة من الذاكرة المحلية (<16ms) مع فحص خلفي للملف النسبي `./agents-state.json` بمهلة AbortController (4s) وتجنب إعادة بناء الـ DOM عند تطابق البيانات.
- **توفير المعالج والبطارية:** إيقاف المزامنة التلقائية عند خروج التبويب من نطاق الرؤية (`visibilitychange`) واستئنافها فوراً عند العودة.
- **تطبيق ويب تقدمي (PWA):** دعم كامل للعمل بلا اتصال وكتطبيق مكتبي مستقل عبر `sw.js` و `manifest.webmanifest`.
- **بحث واختصارات سريعة:** بحث فوري في الذاكرة (Debounced 120ms) واختصارات لوحة مفاتيح سريعة (`/` للبحث، `R` للتحديث، و `1-6` للتنقل).
