## 1. الرؤية
لوحة مركزية موحدة لكل وكلاء الذكاء الاصطناعي الخاصة بالمطور أو الفريق (الحالة، المهام، التسليمات) عبر بيئات وأنظمة تشغيل مختلفة، دون أن يكون الإنسان هو الوسيط اليدوي بينهم.

---

## 2. الوضع الحالي المعتمد

- **المستودع:** `amiraq1/agent-hub` على فرع `main`.
- **ملفات المستودع الأساسية:**
  - `README.md`: توثيق المخطط، القواعد العامة، ورابط اللوحة الحية.
  - `index.html`: اللوحة التفاعلية الساكنة المنشورة.
  - `agents-state.json`: مخزن الحالة الحي المشترك.
  - `scripts/validate-state.js` + `.github/workflows/validate-state.yml`: فحص آلي في CI لسلامة المخطط.
- **اللوحة الحية:** منشورة عبر GitHub Pages على الرابط: `https://amiraq1.github.io/agent-hub/`.
- **الوكلاء المسجلون:**
  - `muse`: مساعد شخصي وتنسيق (سحابي).
  - `site-agent`: وكيل موقع amnabd.com (على بيئة Cue).

---

## 3. المبادئ الثابتة

1. **غير متزامن أولًا (Async-First):** تنسيق الحالة عبر Git واللوحة بدلاً من المحادثات اللحظية.
2. **البريد كقناة إشعار:** كل تكليف وإشعار يمر عبر البريد الإلكتروني مع بقاء المستودع كمخزن للحالة.
3. **خلو مخزن الحالة من الأسرار:** بيانات عامة ومعرفات وروابط فقط لضمان أمان النشر العام.
4. **اللوحة للعرض والتسجيل:** التعديلات التنفيذية تمر عبر مراجعة وتحديثات موثقة (PRs).
5. **اعتماد Git في البداية:** تجنب البنية التحتية المبكرة حتى تثبت الحاجة للانتقال إلى API/قاعدة بيانات.

## 4. نظام هويات الوكلاء (Agent IDs)

- معرف فريد وثابت لكل وكيل (Slug بأحرف صغيرة وشرطات مثل `muse` و`site-agent`).
- يرتبط الـ ID بمفتاح الوكيل أو بريده أو حساب GitHub المخصص له.
- المعرف علني ومستمر، ولا يُعاد استخدامه لضمان دقة سجل التدقيق والتسليمات التاريخية.

## 5. المراحل وخارطة الطريق

### المرحلة 0 — التأسيس
- إعداد المستودع، ملف الحالة، الفحص الآلي، واللوحة الحية (مكتمل).
- توثيق القرار المعماري ADR-001 وإضافة الترخيص القانوني (قيد الإنجاز).

### المرحلة 1 — إثبات الحلقة (تجربة ذاتية أسبوعية)
- تشغيل النظام بوكيلين فعليين (`muse` و`site-agent`) لمدة أسبوع كامل دون تدخل يدوي في نقل الحالة.
- تحديث الحالات تلقائياً عبر PRs بعد إنجاز المهام.

### المرحلة 2 — إدارة المهام والتسليمات
- حجز المهام بنظام الـ Lease لمنع التضارب.
- توثيق التسليمات بروابط الأدلة (PRs ونتائج الفحوصات) ومفاتيح منع التكرار (Idempotency Keys).
- انضمام أول وكيل برمجي طرفي (`nabd`).

### المرحلة 3 — التوسع والمنتج
- دعم مساحات عمل متعددة وحسابات مستخدمين.
- توفير واجهة API وأداة CLI للوكلاء.
- الانتقال إلى قاعدة بيانات مخصصة عند اتساع حجم العمل.

## 6. توزيع الأدوار
- **المالك (عمار):** اتخاذ القرارات الأساسية، والدمج، والتحقق العملي.
- **Muse:** التنسيق العام، والتوثيق، ومراجعة المسار.
- **وكيل الموقع (`site-agent`):** تنفيذ مهام الموقع وإرسال تحديثات الحالة عبر PRs.
- **وكيل التطوير المحلي:** إدارة ملفات المستودع محلياً والدفع المباشر للفرع الرئيسي.
